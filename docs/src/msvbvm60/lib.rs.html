1//! # MSVBVM60 - Visual Basic 6.0 Native Runtime Clone in Rust
2//!
3//! Re-implementation and reverse-engineering study clone of Microsoft's `MSVBVM60.DLL`
4//! (Visual Basic Virtual Machine 6.0).
5//!
6//! ## Overview of MSVBVM60.DLL
7//!
8//! `MSVBVM60.DLL` is the runtime execution engine for all software built with Microsoft
9//! Visual Basic 6.0 (released in 1998, code named "Thunder"). Whether a VB6 program was compiled
10//! to Native Code (x86 machine instructions via an optimizing backend based on MSVC C2) or P-Code
11//! (interpreted bytecode), it depends directly on this DLL.
12//!
13//! ### Key Responsibilities:
14//! 1. **Application Lifecycle (`ThunRTMain`)**:
15//!    - Native VB6 binaries have a minimal entry point that pushes the address of a `VBHeader`
16//!      structure and invokes `ThunRTMain` ("Thunder Runtime Main", ordinal 100).
17//!    - `ThunRTMain` validates the `"VB5!"` magic bytes, initializes COM/OLE apartments,
18//!      registers SEH exception handlers (`__vbaExceptHandler`), loads forms/modules,
19//!      invokes `Sub Main` or creates the initial Form, and manages the Win32 message pump.
20//!
21//! 2. **P-Code Interpreter Engines (`ProcCallEngine`, `MethCallEngine`)**:
22//!    - For applications compiled in P-Code mode, execution is interpreted instruction-by-instruction
23//!      by these engines.
24//!
25//! 3. **Type System and Object Model**:
26//!    - **BSTR**: Length-prefixed (32-bit byte count at offset -4), UTF-16, null-terminated COM strings.
27//!    - **VARIANT**: 16-byte tagged unions (`VT_I4`, `VT_BSTR`, `VT_DISPATCH`, etc.) enabling VB6 dynamic typing.
28//!    - **SAFEARRAY**: Multi-dimensional bounded array descriptors.
29//!    - **Currency (CY)**: 64-bit integer fixed-point with 4 decimal places.
30//!    - **COM Interfaces**: `BASIC_CLASS_*`, `EVENT_SINK_*`, and `Zombie_*` implement `IUnknown` and `IDispatch`.
31//!
32//! 4. **Memory Manipulation (`GetMem*`, `PutMem*`, `VarPtr`)**:
33//!    - Since VB6 lacks native pointer syntax, programmers historically used undocumented runtime
34//!      exports like `VarPtr` (which passes back a variable's address) and `GetMem4`/`PutMem4`
35//!      for direct memory manipulation and high-performance Win32 API interop.
36//!
37//! 5. **VBA Standard Library (`rtc*`)**:
38//!    - Functions like `MsgBox` (`rtcMsgBox`), `DoEvents` (`rtcDoEvents`), `RGB` (`rtcRgb`),
39//!      `InStr` (`rtcInStr`), `Trim` (`rtcTrimBstr`), and `Shell` (`rtcShell`).
40//!
41//! 6. **Compiler Runtime Helpers (`__vba*`)**:
42//!    - String allocation/copying/concatenation (`__vbaStrCopy`, `__vbaStrCat`, `__vbaFreeStr`).
43//!    - Variant math and conversions (`__vbaVarAdd`, `__vbaI4Str`, `__vbaVarMove`).
44//!    - Array allocation and bounds checking (`__vbaAryConstruct`, `__vbaAryLock`).
45//!    - Error handling (`__vbaOnError`, `__vbaExceptHandler`).
46//!
47//! 7. **Calling Conventions**:
48//!    - VB6 on x86 utilizes `__stdcall` (`extern "system"` in Rust) for the vast majority of exports.
49//!    - Specific CRT math routines (`_CI*`, `_adj_fdiv_*`, `_allmul`) use `extern "C"`.
50//!
51//! 8. **Export Ordinals (`msvbvm60.def`)**:
52//!    - Windows DLLs often link by ordinal. This implementation includes a complete `.def` file
53//!      covering all 635 exports ranging from ordinal 100 (`ThunRTMain`) to 2010 (`EbGetVBAObject`).
54//!

108const DLL_PROCESS_DETACH: u32 = 0;
109const DLL_PROCESS_ATTACH: u32 = 1;
110const DLL_THREAD_ATTACH: u32 = 2;
111const DLL_THREAD_DETACH: u32 = 3;
112
113/// Dynamic-link library (DLL) entry point.
114///
115/// Called by the operating system loader when processes or threads
116/// attach to or detach from `MSVBVM60.DLL`.
117///
118/// # Arguments
119/// * `_hinst_dll` - Handle to the DLL module.
120/// * `fdw_reason` - Reason code (`DLL_PROCESS_ATTACH`, `DLL_THREAD_ATTACH`, etc.).
121/// * `_lp_reserved` - Reserved pointer for loader context.
122///
123/// # Returns
124/// `1` (`TRUE`) indicating successful initialization.
125#[no_mangle]
126pub unsafe extern "system" fn DllMain(
127    _hinst_dll: *mut c_void,
128    fdw_reason: u32,
129    _lp_reserved: *mut c_void,
130) -> i32 {
131    match fdw_reason {
132        DLL_PROCESS_ATTACH => {
133            #[cfg(feature = "std")]
134            #[cfg(feature = "trace_calls")]
135            eprintln!("[msvbvm60] DLL_PROCESS_ATTACH: Visual Basic 6.0 Runtime initialized");
136        }
137        DLL_THREAD_ATTACH => {}
138        DLL_THREAD_DETACH => {}
139        DLL_PROCESS_DETACH => {
140            #[cfg(feature = "std")]
141            #[cfg(feature = "trace_calls")]
142            eprintln!("[msvbvm60] DLL_PROCESS_DETACH: Visual Basic 6.0 Runtime uninitialized");
143        }
144        _ => {}
145    }
146    1 // TRUE (success)
147}
